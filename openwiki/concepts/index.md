# Files

- [Signed Envelope Protocol and Anti-Replay](envelope-protocol.md) - HAAP wire format and verification pipeline: the signed JSON envelope fields, deterministic canonical JSON (sorted keys, compact, floats forbidden), sign_body/envelope_from_bytes/verify_envelope stages, the ±300 s timestamp window, the per-sender NonceManager anti-replay with 660 s TTL, the full MESSAGE_TYPES catalog, size caps, the stable on-wire error codes, and the signed error-envelope reply shape.
- [Agent Identity: Ed25519 Keys and HF Fingerprints](identity.md) - How HAAP agent identity works: the locally generated Ed25519 key pair in haap/crypto.py (KeyPair), the HF- fingerprint derived from the first 16 hex of SHA-256 of the raw public key, the Identity dataclass and its versioned identity.json persistence with 0600 permissions under $HAAP_DIR, every place the code enforces that a claimed fingerprint actually matches the verifying public key (bootstrap envelopes, handshake challenges, registries, endpoint refresh), and why the private key never leaves the machine.
- [Capability Manifests and the Well-Known Contract](manifests.md) - What a HAAP agent publishes about itself: the two manifest formats (full haap-capability-manifest-v1 built by build_manifest with Hermes skill introspection, and the public haap-public-manifest-v1 produced by public_manifest and served live at GET /.well-known/haap.json), Hermes skill scanning from the ~/.hermes/skills candidates, the export_manifest/load_manifest/parse_manifest APIs, how manifests are signed for registry registration and re-verified by discovery clients, and the hard no-keys rule enforced on both generation and parsing.
- [Permissions Matrix, Scopes and Named Roles](permissions-and-roles.md) - HAAP's deny-by-default authorization model: the per-friend action matrix (allow flag plus fnmatch glob scopes over a request resource) stored in FriendRecord.permissions and evaluated by PermissionMatrix, the action catalog with its inbound and outbound action lists, the server inbound and client outbound enforcement points, and the named role templates guest/client/partner/family/admin with permission and rate-limit bundles, roles.json overrides with extends, and capping of unknown roles to client in auto-approval policy.
- [Abuse Controls: Token Buckets and Append-Only Audit](rate-limiting-and-audit.md) - HAAP's two abuse-control mechanisms: per-(friend, action) token-bucket rate limiting with a per-friend global bucket, default and per-friend catalogs, and RATE_LIMITED/retry_after semantics; plus the append-only AuditLog JSON-lines file with 5 MB rotation, sensitive-key redaction, in-memory test mode, and what every accepted or rejected decision records.
