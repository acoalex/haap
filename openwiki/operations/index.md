# Files

- [CLI Commands and Runtime Configuration](cli-and-config.md) - The operator-facing surface of the `haap` command (entry `haap.cli:main`): init, whoami, the friends family (list/requests/add/approve/deny/remove/block/roles), capabilities, task list, serve, the registry family (serve/register/search) and audit; how `--dir` and `HAAP_DIR` select the agent state root; the human-editable runtime configuration files roles.json and policy.json (schemas, evaluation order, when each is re-read); the README systemd service example; and which operations are deliberately Python-API only (outbound friendship handshake, task delegation, notifiers).
- [Client Operations and Transport Layers](client-and-transports.md) - The outbound runtime domain of a HAAP agent: HAAPClient construction and operations (start_friendship, delegate_task, service_search/service_book, refresh_endpoint against /.well-known/haap.json), the outbound local permission guard and rate limiter that run before any envelope leaves the machine, error normalization via error_from_code, and the transport contract implemented by MemoryTransport (in-process) and HttpTransport (retryable statuses 408/429/5xx, backoff, timeouts, 202 fire-and-forget).
- [Federated Directory System (Reference Registry)](federated-directory.md) - The HAAP federated directory domain owned by this repo: RegistryStore (in-memory agent index with lazy expiry, entry TTL 24 h, challenge TTL 60 s, MAX_AGENTS 10 000) and RegistryServer HTTP API (/register, /register/complete, /heartbeat, /search, /agents/{fingerprint}, /health) with registry-signed challenges, plus the registry_client utilities (build_registration, register, search, heartbeat, HeartbeatLoop), the haap registry CLI commands, and how this reference code relates to the production directory service scoped in docs/DIRECTORY_SERVICE_BRIEF.md.
- [Messaging Server: Router, HTTP Surface and Callbacks](messaging-server.md) - The inbound runtime domain of a HAAP agent: HAAPServer construction and injectable pieces (audit, permissions, rate limiter, tasks, policy, notifier, on_friend_request, on_task, skills/tools), the handle_message routing pipeline with bootstrap sender-key resolution (BOOTSTRAP_TYPES), the _on_<mtype> handler registration convention and per-type handlers, signed error-envelope replies, the HTTP surface (POST /haap/messages, GET /.well-known/haap.json, GET /health) with its 200/202/400 status mapping, the live well_known_manifest, and how haap serve runs it.
